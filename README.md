# AI-Vector-Engine

![VectorDB Banner](https://img.shields.io/badge/AI-Vector_Engine-00F0FF?style=for-the-badge&logo=c%2B%2B&logoColor=white&labelColor=03030A)

A highly optimized, custom-built Vector Database engine completely written in C++ from scratch, featuring an immersive Cyber-Neon Glassmorphic Web UI and seamless integrations with local LLMs via Ollama. 

Built and maintained by [Shikhar-Kesharwani](https://github.com/Shikhar-Kesharwani).

## 🌟 Key Features

*   **⚡ Ultra-Fast Search Algorithms:** Implements core vector-search algorithms from scratch in pure C++, including:
    *   **HNSW** (Hierarchical Navigable Small World) for blazing fast approximate nearest neighbor search.
    *   **KD-Tree** for structured, precise spatial lookups.
    *   **Brute Force** exact-match k-NN for baseline testing.
*   **🧠 Local RAG (Retrieval-Augmented Generation):** Connects to your local Ollama instance (`llama3.2` and `nomic-embed-text`) to perform embeddings and AI chat right over your data.
*   **🎨 Immersive Cyber-HUD Interface:** Features a completely custom-built, unique UI.
    *   **Immersive Layout**: The 2D PCA vector scatter plot forms an interactive background for the entire application.
    *   **Frosted Glass & Holographic Elements**: Floating glass panels, neon-cyan/magenta glow effects, and modern 'Inter' typography.
*   **🛠️ Zero External DB Dependencies:** Everything from HTTP serving to JSON parsing and multithreaded vector indexing is baked natively into the core engine.

## 🚀 Getting Started

### Prerequisites
1.  **C++ Compiler (g++)**: Requires MinGW-w64 or an equivalent environment capable of compiling C++17 with pthreads.
2.  **Ollama**: Install [Ollama](https://ollama.com/) locally.

### 1. Download Local AI Models
Open your terminal and run these commands to download the necessary embedding and conversational models:
```bash
ollama pull nomic-embed-text
ollama pull llama3.2
```

### 2. Compile the Engine
Clone the repository and compile the core database server using `g++`:

```bash
# Clone the repository
git clone https://github.com/Shikhar-Kesharwani/OWN_AI_BUILD.git
cd AI-Vector-Engine

# Compile using g++ with pthread support
g++ -O3 -std=c++17 -o db.exe main.cpp -lpthread
```

### 3. Run the Database
Launch the newly compiled server:
```bash
./db.exe
```

The database will initialize, and the interactive Cyber-HUD UI will be available in your browser at:
**[http://localhost:8080](http://localhost:8080)**

## 💻 Usage

1.  **Index Documents:** Navigate to the "Documents" tab and paste raw text. The application will chunk the text, call Ollama for embeddings, and inject the vectors into the core C++ engine.
2.  **Compare Algorithms:** Try searching for terms and dynamically switch between `HNSW`, `KD-Tree`, and `Brute Force` to compare latency times displayed in real-time.
3.  **Ask AI:** Switch to the "Ask AI" tab to ask questions. The engine will perform a vector search against your documents, retrieve the most relevant chunks, and stream an answer generated by `llama3.2`.

## 🚀 Cloud Deployment Architecture

This project is fully optimized for cloud deployment with 100% parity to the local development environment. It supports a dual-architecture deployment model:

### 1. Platform Native (PaaS)
Pre-configured for zero-downtime deployment on platforms like Render, Vercel, or Firebase.
- Native configuration files (e.g., ender.yaml) are included for one-click deployments.
- Environment variables prioritize cloud APIs (Groq, Gemini, OpenAI) to ensure compatibility with free-tier memory limits.

### 2. Dockerized Containers
For isolated, infrastructure-agnostic deployment on VPS or Cloud Run.
- **Multi-stage Dockerfile**: Optimized for lightweight, fast builds.
- **docker-compose.yml**: Configured with strict health checks, network isolation, and unless-stopped restart policies.
- Automatically handles local dependencies and avoids local OOM crashes by prioritizing cloud inference APIs.

### 🔄 CI/CD Pipeline
Continuous Integration and Deployment is handled via GitHub Actions.
- Workflows are configured in .github/workflows/ to automatically test and deploy changes pushed to the main branch.
